# 소단원별 발화 사다리 백그라운드 분석 설계

## 목표

동일 학습자가 같은 소단원의 반복학습을 가장 최근 세션 기준으로 연속 두 번 완료하면, 별도 알림 없이 분석 작업을 등록한다. Mormi-AI는 저장된 발화 사다리 모델과 규칙 정책을 백그라운드에서 실행하고, 교사용 주간 리포트는 실제 발화 근거와 소단원별 다음 단계 추천을 함께 표시한다.

분석은 추천만 생성하며 학습자의 실제 시작 단계를 자동 변경하지 않는다. 교사가 리포트에서 추천을 승인한 뒤 다음 학습 세션부터 해당 소단원의 시작 단계에 적용한다.

## 용어와 트리거

- 소단원 키는 기존 `curriculum_session_id` 및 AI의 `skill_id`를 사용한다.
- 연속 두 번은 학습자의 가장 최근 완료 학습 세션 두 건이 동일한 소단원인 경우다.
- 이미 처리한 두 번째 세션은 멱등 키로 다시 분석하지 않는다.
- 완료 응답은 분석 완료를 기다리지 않는다. 분석 작업 등록 이후 기존 학습 완료 응답을 즉시 반환한다.

## 전체 흐름

1. Mormi-BE가 학습 세션 완료 트랜잭션을 확정한다.
2. 완료 후 가장 최근 두 세션이 같은 소단원인지 검사한다.
3. 조건을 만족하면 해당 두 세션의 단계별 반복학습 시도와 정답률을 정규화해 Mormi-AI 내부 분석 API에 멱등 작업을 등록한다.
4. Mormi-AI는 작업을 DB에 `pending`으로 저장하고 즉시 접수 응답을 반환한다.
5. AI 백그라운드 작업자가 모델을 한 번만 로드한 뒤 작업을 처리한다.
6. 최근 실제 발화는 모델로 L2/L3/L4를 예측한다. `no_response`, `choice`, `solve_together`는 모델에 넣지 않고 규칙 정책으로 처리한다.
7. 결과를 소단원별 최신 분석으로 저장하고 내부 리포트 근거 응답에 포함한다.
8. Mormi-BE가 주간 리포트 DTO에 분석 결과를 연결하고 Mormi-FE가 최하단 추천 카드에 표시한다.

## 판정 정책

지원 단계 순서는 `L0 < L2 < L3 < L4`다.

- 모델 예측 대상: 원문이 존재하는 `free_text`, `short_answer`.
- 규칙 대상: `no_response`는 한 단계 낮춤, `choice`는 L2, `solve_together`는 L0.
- 현재 단계 정답률은 트리거가 된 같은 소단원 최근 두 세션에서 해당 단계의 유효 시도로 계산한다.
- 승급은 최근 두 세션, 현재 단계의 채점 가능한 시도 4건 이상, 최근 유효 발화 2건 이상을 요구한다.
- 정답률이 90% 이상이고 최근 유효 발화 예측 두 건이 모두 다음 단계 이상이면 한 단계 승급을 추천한다. L4는 유지한다.
- 하향은 최근 유효 발화 또는 규칙 판정 두 건이 연속으로 현재보다 낮거나, 현재 단계 정답률이 70% 미만이면서 최근 낮은 단계 근거가 있을 때 한 단계 조정을 추천한다.
- 하향은 `L4 → L3 → L2 → L0` 순서로 한 단계씩만 적용한다. 모델은 L2/L3/L4를 판정하고 L0는 반복된 `solve_together` 또는 동등한 규칙 근거로만 추천한다.
- 그 외에는 현재 단계를 유지한다.
- 결과 상태는 `UPGRADE`, `MAINTAIN`, `ADJUST_DOWN`, `INSUFFICIENT_EVIDENCE` 중 하나다.
- 모델의 L3 한계가 남아 있으므로 결과에는 신뢰도와 근거 발화 수를 포함하고 교사용 추천으로만 사용한다.

학습 중 `잘 모르겠어요` 또는 연속 오답으로 내려가는 지원 단계는 해당 세션 안에서만 즉시 적용한다. 주간 시작 단계는 이 실시간 지원과 별도로 유지되며 교사 승인 없이 영구 변경되지 않는다.

## Mormi-AI

### 저장 구조

새 분석 작업/결과 테이블은 다음 정보를 저장한다.

- 멱등 작업 키와 트리거 학습 세션 ID
- 학습자 ID, 소단원 ID
- 현재 단계와 단계별 정답/시도 수
- 작업 상태 `pending/running/completed/failed`
- 예측 단계, 추천 단계, 추천 상태, 모델 신뢰도
- 사용한 발화 수와 모델/정책 버전
- 생성·시작·완료 시각 및 제한된 오류 코드

발화 원문은 새 분석 테이블에 복제하지 않는다. 기존 보존 동의와 암호화 정책을 따르는 `turns`에서 처리 시점에만 읽는다.

### 실행기

- `MORMI_LADDER_MODEL_DIR`에 저장 모델이 있을 때만 모델 경로를 활성화한다.
- 모델은 작업마다 다시 로드하지 않고 프로세스에서 지연 로드 후 재사용한다.
- DB 폴링 작업자는 미완료 작업을 가져와 처리하며 재시작 뒤에도 `pending` 작업을 이어간다.
- 모델이 없거나 원문을 사용할 수 없으면 규칙 근거만 사용하거나 `INSUFFICIENT_EVIDENCE`로 종료한다.
- 한 작업 실패가 대화 API나 다른 작업을 중단시키지 않는다.

### 내부 계약

- 작업 등록 API는 Mormi 서비스 키를 요구한다.
- 내부 리포트 근거 응답은 학습자별 최신 소단원 분석 목록을 추가한다.
- 기존 리포트 근거 필드는 유지해 하위 호환성을 보장한다.

## Mormi-BE

- 학습 완료 후 커밋된 데이터를 기준으로 트리거를 평가한다.
- 가장 최근 완료 세션 두 건의 동일 소단원 여부를 서버 데이터로 판정한다.
- 두 세션의 `drill` 시도 중 `answer_meta.expression_level`을 표준 L0/L2/L3/L4로 정규화한다.
- AI 작업 등록 실패는 학습 완료를 실패시키지 않는다. 제한된 오류 코드만 기록하고 재등록 가능한 멱등 키를 사용한다.
- 진단 리포트 응답에 소단원별 `ladder_recommendations`를 추가한다.
- 교사 승인 API는 분석 ID와 추천 버전을 받아 멱등 처리하고, 승인된 단계만 AI 학습자 소단원 프로필에 반영한다.
- 분석 이후 새 기록으로 추천 버전이 바뀌면 이전 승인 요청을 거부해 오래된 추천이 적용되지 않게 한다.

## 실제 발화 및 AI가 본 변화

현재 발화 API는 동일 과제에서 동일 검증 요소를 새로 확인한 발화 쌍만 허용해 실제 발화 대부분을 제외한다.

새 선택 순서는 다음과 같다.

1. 기존의 강한 검증 조건을 만족하는 과거·최근 발화 쌍을 우선 사용한다.
2. 없으면 같은 소단원의 검증된 실제 응답 중 가장 이른 발화와 최근 발화를 사용한다.
3. 발화가 한 건이면 최근 발화만 반환한다.
4. 원문 보존 동의가 없거나 보존 기간이 끝났으면 원문을 표시하지 않는다.

`AI가 본 변화`의 상단 문장은 기존 수치 사실 요약과 발화 분석 결과를 함께 근거로 삼는다. AI 요약이 검증에 실패하면 백엔드가 예측 단계, 정답률, 실제 발화 존재 여부로 만든 검증 가능한 기본 문장을 표시한다.

## Mormi-FE

- 발화 근거 DTO는 `past`를 선택값으로 허용하고 최근 발화 한 건만 있는 상태를 표현한다.
- `AI가 본 변화` 펼침 영역은 실제 과거·최근 발화 또는 최근 발화 한 건을 표시한다.
- 리포트 최하단에 선택한 소단원의 분석 카드를 표시한다.
- 카드에는 최근 예측 단계, 해당 단계 정답률, 추천 상태, 추천 단계, 근거 발화 수, 분석 시각을 표시한다.
- 승급 또는 하향 추천에는 교사용 `이 단계로 적용` 버튼을 표시한다. 유지는 별도 승인이 필요 없다.
- 승인 성공 뒤에는 적용된 단계와 다음 세션부터 반영된다는 상태를 표시한다.
- 분석 전에는 `반복학습을 두 번 완료하면 자동으로 분석합니다`라고 표시하며 별도 팝업이나 학습자 알림은 만들지 않는다.

## 오류 처리와 개인정보

- 분석 실패는 학습 완료와 리포트 전체 조회를 실패시키지 않는다.
- 모델 미설정, 원문 미보존, 근거 부족을 서로 다른 상태로 구분한다.
- 로그에는 발화 원문, 암호화 키, 서비스 키를 기록하지 않는다.
- 교사용 리포트의 기존 인증과 학습자 범위 검증을 그대로 적용한다.
- 추천 결과는 교사의 검토 대상이며 학습자 프로필을 자동 변경하지 않는다.

## 검증

- BE 단위 테스트: 동일 소단원 최근 두 세션만 작업을 등록하고 재요청은 중복 등록하지 않는다.
- AI 단위 테스트: 규칙/모델 라우팅, 90% 승급, 낮은 단계 조정, 근거 부족, 멱등 처리.
- AI 통합 테스트: pending 작업이 완료 결과로 바뀌고 내부 리포트 근거에 포함된다.
- BE 리포트 테스트: 최신 소단원 추천과 실제 발화 한 건/두 건/없음이 DTO에 정확히 반영된다.
- FE 테스트: 추천 카드 상태와 최근 발화 단독 표시를 검증한다.
- 기존 AI·BE·FE 전체 테스트와 린트·타입 검사를 실행한다.
